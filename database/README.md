# 낙원레코드 로컬 DB 준비

팀원 각자가 자신의 MySQL에서 실행할 수 있도록 테이블 생성과 음반 목업을 분리했습니다. 실제 운영 데이터가 아닌 개발·시연용입니다.

## 실행 전 확인

- MySQL 8.0.16 이상에서 실행합니다. 서버가 켜져 있어야 합니다.
- 쿼리는 `nakwon_records` DB를 사용합니다. 같은 이름의 기존 DB나 데이터가 있다면 내용을 먼저 확인하고 실행하지 마세요.
- 계정에 DB 생성과 테이블 생성 권한이 필요합니다. 접속 정보는 깃에 올리지 않습니다.
- `01`은 새 DB 초기 생성용입니다. 테이블이 이미 있으면 기존 구조를 고치지 않고 오류가 납니다.
- `02`는 `albums` 테이블이 비어 있을 때 **한 번만** 실행합니다. 반복하면 중복되거나 추천 설정 오류가 발생할 수 있습니다.

## 실행 순서

1. MySQL Workbench 등에서 자신의 MySQL 서버에 접속합니다.
2. `01_테이블_생성.sql`을 열어 전체 실행합니다. 회원·음반·장바구니·주문·주문항목·리뷰·찜·추천 설정 등 8개 테이블이 만들어집니다.
3. `02_음반_목업데이터.sql`을 열어 전체 실행합니다. 장르당 3개씩 음반 18개와 음반별 추천 설정이 들어갑니다.
4. 테이블과 데이터를 확인합니다.

```sql
USE nakwon_records;
SHOW TABLES;
SELECT genre, COUNT(*) AS album_count FROM albums GROUP BY genre;
SELECT title, genre, format, stock, hidden FROM albums ORDER BY genre, id;
```

`stock`이 0이면 품절, `hidden`이 1이면 일반 사용자 화면에서 숨겨야 하는 음반입니다. 비공개 2개를 포함해 전체 18개이며, 공개 목록에는 16개가 보입니다. LP·CD와 여유 재고·적은 재고·품절을 섞었습니다.

추천 설정은 음반마다 1개씩 생성하며, 공개 상태이고 재고가 있는 대표 음반 6개에만 추천을 켰습니다. 리뷰·회원·주문 데이터는 넣지 않습니다.

음반 제목과 아티스트는 가상입니다. 이미지 주소는 모두 NULL이므로 프론트에서 공통 대체 이미지 `/images/albums/placeholder.svg`를 표시하도록 연결해 주세요. 실제 표지 파일을 추가한 뒤 이미지 주소를 수정할 수 있습니다.

이 SQL은 팀원이 각자의 MySQL에서 실행하는 파일입니다. 한 사람의 데이터 변경이 다른 사람의 DB에 자동 반영되지는 않습니다.
