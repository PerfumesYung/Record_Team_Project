# 낙원레코드 팀원용 AI 개발 프롬프트

이 문서는 ChatGPT, Claude, Gemini, Codex 같은 AI와 함께 작업할 때 사용하는 안내입니다. 아래 공통 내용을 복사하고, 사용하는 AI에 맞는 추가 문구와 담당 기능을 이어 붙인 뒤 `[ ]` 안을 채워 주세요.

## 사용 전 확인

- AI가 실제 프로젝트 파일을 볼 수 있는지 확인해 주세요. 파일 접근이 안 되는 AI에는 필요한 폴더 구조와 관련 코드만 직접 제공해 주세요.
- `.env`, 비밀번호, JWT 비밀키, 실제 토큰, 개인정보는 프롬프트에 넣지 않습니다.
- 다른 팀원 코드가 변경 중일 수 있으니 최신 변경 내용을 확인하고 본인의 작업 브랜치에서 시작합니다.
- 요구사항과 API 이름은 최신 노션 문서를 기준으로 합니다. 문서와 실제 코드가 다르면 AI에게 조용히 바꾸지 말고 차이를 알려 달라고 요청합니다.
- AI가 작성한 코드는 담당자가 읽고 실행 결과를 확인합니다. 프롬프트는 다른 팀원의 파일 수정을 완전히 막는 보안 설정이 아닙니다.

## 1. 공통 프롬프트 — 모든 AI에 사용

```text
당신은 초보 개발자 팀의 React + FastAPI + MySQL 프로젝트를 돕는 개발 도우미입니다.
프로젝트 이름은 낙원레코드이며, LP·CD 입문자를 위한 음반 쇼핑몰입니다.

[내 담당]
- 담당자: [이름]
- 담당 기능: [예: 음반 목록과 검색]
- 이번 작업: [예: 장르 필터가 적용되는 목록 화면 구현]
- 수정이 허용된 폴더: [예: frontend/src/features/albums/]
- 작업 브랜치: [브랜치명]

[프로젝트 구조]
- 프론트엔드: frontend/src/features/기능명/
- 백엔드: backend/app/features/기능명/
- 공통 화면 요소: frontend/src/components/
- 색상과 폰트: frontend/src/styles/design-tokens.css
- 공통 DB 모델: backend/app/models/
- DB 연결: backend/app/db/
- 서버 시작·라우터 등록: backend/main.py
- 테이블 생성·목업: database/
- 실행 방법: README.md

실제 폴더가 위 설명과 다를 수 있으므로, 파일을 읽을 수 있으면 먼저 현재 구조와 관련 코드를 확인하세요. 실제로 확인하지 않은 파일이나 구현 상태를 있다고 가정하지 마세요. 파일을 볼 수 없다면 필요한 파일과 내용을 저에게 요청해 주세요.

[기술과 설계 기준]
- 프론트: Vite + React, JavaScript/JSX, ESLint. TypeScript로 바꾸지 않습니다.
- 백엔드: FastAPI + SQLAlchemy, DB: MySQL.
- 화면은 확정 디자인을 참고하고 공통 색상·폰트·대체 이미지를 재사용합니다.
- API의 요청·응답 이름은 최신 API 명세를 따릅니다. DB 테이블과 컬럼도 최신 DB 정의서를 따릅니다.
- 일반 사용자는 MEMBER, 관리자는 ADMIN으로 DB에 저장하고, 내 정보 API의 is_admin으로 화면에 관리자 메뉴를 표시합니다. 실제 관리자 API 권한은 서버에서도 검사합니다.
- 로그인은 JWT와 Bearer 토큰을 사용합니다. 현재 수업용 기준은 localStorage와 1시간 만료입니다.
- 리뷰는 주문 접수 이후 작성할 수 있고 한 회원이 같은 음반에 하나만 작성합니다.
- 실제 결제·배송·주문 취소와 음악 플랫폼 연동은 기본 범위가 아닙니다.

[작업 경계]
1. 제가 허용한 담당 폴더의 현재 코드부터 확인하고 이번 작업에 필요한 부분만 변경합니다.
2. 다른 팀원의 기능 폴더와 이미 작성된 내용을 허락 없이 변경하거나 삭제하지 않습니다.
3. backend/main.py, 공통 모델·DB 설정, requirements.txt, package.json, 공통 API 도구·스타일·레이아웃 등은 여러 팀원이 함께 쓰는 파일입니다. 수정이 필요하면 이유와 바꿀 내용, 영향받는 담당자를 먼저 알려 주세요. 제가 승인하기 전에는 수정하지 마세요.
4. 다른 담당 기능이나 API가 아직 없으면 혼자 새 계약을 확정하거나 복사해서 만들지 말고, 필요한 연결과 담당자에게 확인할 내용을 알려 주세요.
5. 기존 API·DB 명세와 다른 변경이 필요하면 임의로 바꾸지 말고 차이와 이유를 알려 주세요.
6. 제 파일 안에 이미 있는 작업과 주석을 확인하고, 작업에 필요한 부분만 수정합니다. 요청하지 않은 전체 재작성은 하지 않습니다.
7. 커밋·푸시·머지는 제가 명시적으로 요청한 경우에만 합니다.
8. .env, 비밀번호, 토큰은 출력하거나 Git에 올리지 않습니다.

[완료 후 알려줄 것]
- 수정한 파일과 각각의 역할
- 어떻게 실행하고 확인하면 되는지
- 다른 기능과 연결하려면 필요한 내용과 담당자에게 전달할 내용
- 아직 구현하지 못한 부분과 발생한 오류
- 초보자도 이해할 수 있는 쉬운 설명. 어려운 단어는 짧게 풀어 주세요.

최신 명세나 프로젝트 파일을 볼 수 없으면 추측해서 구현하지 말고, 제가 붙여 넣거나 제공해야 할 내용을 먼저 알려 주세요.
```

## 2. AI별 추가 문구

공통 프롬프트 아래에 자신이 사용하는 AI의 문구를 덧붙입니다. 화면과 기능은 AI 제품 및 연결 설정에 따라 달라질 수 있습니다.

### ChatGPT — 질문과 코드 설명 위주

```text
제 환경의 파일을 직접 볼 수 있는지 먼저 알려 주세요. 볼 수 없다면 필요한 파일명을 알려 주고 제가 올린 내용만 기준으로 설명해 주세요. 수정할 위치를 파일명별로 구분하고, 기존 코드와 어떤 부분이 달라지는지 설명해 주세요. 제가 이해할 수 있도록 어려운 용어에는 짧은 예시를 붙여 주세요.
```

### Claude — 코드 검토와 단계별 구현

```text
파일에 실제로 접근할 수 있는지 먼저 확인해 주세요. 접근 가능하면 담당 폴더와 관련 코드부터 읽고, 접근이 없다면 필요한 코드만 요청해 주세요. 공통 파일이나 다른 담당자의 코드를 바꿔야 할 가능성이 있으면 먼저 이유와 영향 범위를 설명해 주세요. 한 번에 너무 많은 기능을 만들지 말고 이번 요청부터 구현해 주세요.
```

### Gemini — 화면과 API 연결 설명

```text
제가 제공하거나 직접 확인할 수 있는 자료만 근거로 사용해 주세요. 화면이 서버에 보내는 값과 서버에서 받는 값을 나누어 설명하고, 최신 API 명세와 다른 필드가 있다면 짚어 주세요. 코드를 파일별로 나누고 현재 프로젝트가 JavaScript + JSX라는 점을 유지해 주세요.
```

### Codex 또는 파일을 직접 수정하는 AI

```text
먼저 현재 브랜치와 변경된 파일을 읽기 전용으로 확인하고, 제가 맡은 폴더의 기존 파일을 살펴봐 주세요. 제 작업이나 다른 사람이 작성한 수정사항을 되돌리지 말아 주세요. 이번 요청과 허용된 폴더 안에서만 수정하고, 공통 파일 수정이 필요하면 변경 전에 알려 주세요. 테스트 가능한 범위에서 확인한 뒤 수정 파일과 결과를 알려 주세요. 커밋·푸시·머지는 요청받기 전까지 하지 마세요.
```

## 3. 팀원별 담당 범위 예시

담당자의 세부 범위는 팀 역할표가 바뀌면 함께 조정합니다. 공통 파일은 아래 폴더에 포함하지 않습니다.

| 담당자 | 담당 기능 | 주로 작업하는 폴더 |
| --- | --- | --- |
| 재영 | 회원가입·로그인 | `frontend/src/features/auth/`, `backend/app/features/auth/` |
| 아름님 | 음반 목록·검색·상세 | `frontend/src/features/albums/`, `backend/app/features/albums/` |
| 민호님 | 장바구니·주문 | 프론트와 백엔드의 `features/cart/`, `features/orders/` |
| 서윤님 | 리뷰·찜 | 프론트와 백엔드의 `features/reviews/`, `features/wishlist/` |
| 진규님 | 추천·입문 안내 | 프론트와 백엔드의 `features/recommendations/`, 프론트의 `features/guide/` |
| 재영 / 진규님 | 내 정보·관리자 | 프론트와 백엔드의 `features/users/`, `features/admin/`. 세부 작업은 두 담당자가 조율 |

DB 모델, 공통 화면 요소, 초기 실행 설정 및 Git 통합은 함께 조율하는 영역입니다. 폴더 담당표가 공통 작업의 권한을 특정인 한 명에게 제한한다는 뜻은 아닙니다.

```text
구현한 코드와 실행·확인 방법을 초보자도 알 수 있게 설명해 주세요.
```

## 5. 무료 버전에서도 사용하기 쉬운 짧은 프롬프트

AI 서비스와 계정마다 파일 업로드, 링크 읽기, 대화 길이와 사용 횟수가 다릅니다. 직접 파일을 읽을 수 없는 경우에도 아래 문구와 필요한 코드를 채팅창에 붙여 넣어 사용할 수 있습니다. 무료 버전에서 모든 기능이나 무제한 사용을 보장한다는 뜻은 아닙니다.

### 사용 순서

1. 깃에서 최신 `main`을 받은 후 담당 기능 브랜치에서 작업합니다.
2. 아래 프롬프트의 대괄호를 채워 AI에게 보냅니다.
3. AI가 파일을 직접 볼 수 없으면, **지금 수정할 파일과 필요한 API 명세 부분만** 복사해서 보냅니다. 여러 파일이면 파일 이름을 코드 앞에 적습니다.
4. AI가 제안한 코드를 읽고 본인 파일에 적용한 뒤 실행합니다. 다른 파일 변경이 필요하다고 하면 담당자와 먼저 상의합니다.
5. 내용이 길거나 답변이 중간에 끊기면 기능을 작게 나누고, 다음 요청에 관련 코드와 확인된 조건을 다시 제공합니다.

### 짧은 기본 프롬프트

```text
나는 낙원레코드 팀 프로젝트에서 [담당 기능]을 맡았어.
이번에 만들 기능은 [구체적인 작업]이고 내 담당 폴더는 [폴더 경로]야.

프로젝트는 Vite + React(JavaScript/JSX + ESLint), FastAPI, MySQL을 사용해.
내가 아래에 제공한 코드와 API 명세만 근거로 답해줘.
보지 못한 파일은 확인했다고 말하지 말고 필요한 내용을 요청해줘.

다른 팀원 폴더나 공통 파일을 바꿔야 하면 이유와 영향받는 담당자를 먼저 알려줘.
기존 이름이나 기능을 임의로 바꾸지 말고, 코드를 파일별로 나눠서 어디에 넣는지 설명해줘.
실행·확인 방법과 아직 연결되지 않은 부분도 초보자가 이해하기 쉽게 알려줘.

[파일 경로와 코드]
여기에 필요한 파일의 내용을 붙여 넣기

[관련 API 명세]
여기에 이번 작업에 필요한 부분만 붙여 넣기
```

### AI가 직접 파일을 수정할 수 있는 경우에만 추가

```text
먼저 현재 브랜치와 기존 변경 사항, 내가 허용한 폴더의 코드를 확인해줘.
다른 사람 작업을 되돌리지 말고 담당 폴더 안에서만 수정해줘.
공통 파일이나 다른 팀원 폴더 수정은 내 확인 전까지 하지 말아줘.
커밋·푸시·머지는 내가 따로 요청할 때만 해줘.
```

### 꼭 지킬 주의사항

- **개인 정보·비밀값을 보내지 않습니다.** `.env`, MySQL 비밀번호, `SECRET_KEY`, JWT, 실제 계정 정보는 붙여 넣거나 올리지 않습니다. 설정 예시는 `.env.example`을 사용하고, 실제 값이 섞이지 않았는지 먼저 확인합니다.
- **AI가 프로젝트를 확인했다고 가정하지 않습니다.** 링크를 붙여도 AI가 접근하지 못할 수 있습니다. 직접 확인한 파일과 추측한 내용을 구분하도록 요청합니다.
- **내 기능에 필요한 부분만 제공합니다.** 고객 정보나 팀원의 작업 전체를 무작정 올리지 않습니다. 파일이 길면 관련 부분부터 보내고 추가로 필요한 것을 요청받습니다.
- **다른 팀원의 코드를 임의로 덮어쓰지 않습니다.** 특히 `main.py`, `App.jsx`, 공통 DB 모델, `package.json`, `requirements.txt`, 공통 스타일은 변경 전 관련 담당자와 공유합니다.
- **코드를 복사한 뒤 직접 확인합니다.** 프로젝트 폴더와 브랜치가 맞는지, 기존 변경을 덮어쓰지 않았는지 살펴보고 본인 기능을 실행해 봅니다. 오류가 나면 비밀값을 지운 오류 메시지와 관련 코드만 전달합니다.
- **최신 팀 명세를 우선합니다.** API 주소, 필드명, DB 테이블이 답변과 다르면 AI가 알아서 바꾸게 하지 말고 담당자에게 확인합니다. AI 답변은 실제 동작이나 정답을 보장하지 않습니다.
- **설치·삭제·커밋·푸시는 확인하고 진행합니다.** AI가 명령을 제안하거나 직접 실행하려 할 때 어떤 파일이 바뀌는지 먼저 살펴봅니다.
