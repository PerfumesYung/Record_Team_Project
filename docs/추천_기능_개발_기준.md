# 추천 기능 개발 기준

이 문서는 팀이 정한 추천 기능의 구현 기준입니다. 아직 추천 API가 완성되었다는 뜻은 아닙니다. API 경로와 응답 필드는 노션의 최신 API 명세를 기준으로 확인합니다.

## 추천 대상

아래 조건을 모두 만족하는 음반을 추천 후보로 사용합니다.

- 관리자가 추천 대상으로 설정한 음반: `album_recommendations.enabled = 1`
- 공개 상태인 음반: `albums.hidden = 0`
- 주문할 수 있도록 재고가 있는 음반: `albums.stock > 0`

`album_recommendations.album_id`는 `albums.id`를 참조합니다. 음반 정보는 `albums`에서, 추천 여부와 이유는 `album_recommendations`에서 가져옵니다.

## 입력 조건에 따른 조회 순서

| 입력한 조건 | 결과를 찾는 순서 |
| --- | --- |
| 아티스트와 장르 | 아티스트와 장르 모두 일치 → 장르 일치 → 전체 추천 후보 |
| 아티스트만 | 아티스트 일치 → 전체 추천 후보 |
| 장르만 | 장르 일치 → 전체 추천 후보 |
| 둘 다 없음 | 전체 추천 후보 |

아티스트 이름은 입력한 글자가 포함되는 음반을 찾는 방식으로 시작합니다. 예를 들어 `Park`를 입력하면 `June Park`도 찾습니다. 오타 교정이나 비슷한 아티스트 추천은 기본 범위에 포함하지 않습니다.

각 단계에 결과가 **하나도 없을 때만** 다음 단계로 넘어갑니다. 결과가 일부만 있는 경우 다른 단계의 결과를 섞어 채우지 않습니다. 어느 단계든 위의 공개·재고·추천 설정 조건을 동일하게 적용합니다.

## 화면 안내 예시

- 장르만 일치하는 결과로 대체: “선택한 아티스트의 음반이 없어 같은 장르의 음반을 보여드려요.”
- 전체 추천 후보로 대체: “조건에 맞는 음반이 없어 다른 추천 음반을 보여드려요.”
- 전체 추천 후보도 없음: “현재 추천할 수 있는 음반이 없어요.”

대체 여부는 응답에서 정한 `is_fallback` 등 최신 API 명세와 맞춰 처리합니다. 대체 단계별 안내 문구를 정확히 구분하는 데 필요한 정보가 기존 응답에 없으면 임의로 응답 필드를 추가하지 말고 프론트·백엔드 담당자와 협의합니다.

## 모델과 목업 데이터

- `backend/app/models/album.py`: 음반 공통 모델 `Album`
- `backend/app/models/album_recommendation.py`: 추천 설정 공통 모델 `AlbumRecommendation`
- `database/01_테이블_생성.sql`: MySQL 테이블 생성 SQL
- `database/02_음반_목업데이터.sql`: 음반과 추천 설정 목업 데이터

각 팀원은 자신의 MySQL에 기존 SQL을 실행해 테이블과 데이터를 만듭니다. 이미 실행했다면 중복 데이터나 오류가 생기지 않도록 먼저 DB 상태를 확인합니다. 모델 파일만으로 테이블이 자동 생성되지는 않습니다. 목업이 부족할 때는 기존 데이터와 중복되지 않도록 팀에서 협의 후 추가합니다.
